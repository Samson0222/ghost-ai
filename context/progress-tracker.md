## Recent Fixes

- **Drag-and-drop (round 3)** — Root cause identified and fixed: `onDragOver` was conditionally calling `e.preventDefault()` only when `e.dataTransfer.types.includes(SHAPE_DRAG_TYPE)` passed. If that check fails at runtime (e.g., `DOMStringList.includes` throws vs returning false in certain browser contexts, or the type isn't yet in the list), `preventDefault()` is never called and the browser silently suppresses the `drop` event entirely. Fix: `onDragOver` now unconditionally calls `e.preventDefault()` and sets `dropEffect="copy"`; `onDrop` already guards against non-shape drops via `if (!raw) return`.
- **Drag-and-drop (round 4)** — Replaced React synthetic `onDragOver`/`onDrop` props on `<ReactFlow>` with native `addEventListener("dragover")` / `addEventListener("drop")` on a `ref`'d wrapper div. React's synthetic event delegation fires after the browser has already decided whether to accept the drop, so `e.preventDefault()` on a synthetic `dragover` may not reliably unlock the drop target — native listeners execute at the DOM event level and guarantee it works. The `useEffect` re-attaches handlers when `screenToFlowPosition` or `onNodesChange` change. Also: `ShapePanel` icons get `pointer-events-none` to ensure the drag always starts from the button (not the SVG child), and `handleDragStart` now sets `text/plain` as a fallback MIME type alongside `application/x-ghost-shape`; the drop handler reads either type.
- **Drag-and-drop (round 5)** — Wrapper-level native drag/drop listeners now run in the capture phase, before React Flow pane handlers can consume the drop event. The drop path still writes through Liveblocks React Flow's `onNodesChange([{ type: "add", item }])`, and payload parsing now validates shape, width, and height against `NODE_SHAPES` before creating a canvas node. `npm run build` passes.

## Architecture Decisions

- Dark only — no light mode. All color tokens defined in `globals.css` as CSS custom properties, mapped to Tailwind via `@theme inline`. shadcn variables point to design system tokens so components inherit the dark theme automatically.
- shadcn components live in `components/ui/` and are not modified after generation.
- `--radius` base is `0.75rem`; `@theme inline` derives `radius-xl/2xl/3xl/4xl` from it to match the border-radius scale in ui-context.md.
- Route groups: `app/(auth)/` for sign-in and sign-up pages (no EditorShell); `app/(editor)/` for the editor workspace (EditorShell via group layout). Root layout provides only ClerkProvider + html/body; no page-level chrome.
- `proxy.ts` (Next.js 16 name for middleware) defines public routes from `NEXT_PUBLIC_CLERK_SIGN_IN_URL` / `NEXT_PUBLIC_CLERK_SIGN_UP_URL` env vars; all other routes are protected by `auth.protect()`.
